# 故障排除与常见问题

本文档汇总使用TdxDllGenerator过程中的常见问题及解决方案。

---

## 一、生成阶段问题

### 1.1 配置文件错误

#### 问题：生成器提示"配置文件格式错误"

**症状**：
```
Error: 配置文件解析失败
System.Text.Json.JsonException: 'p' is an invalid start of a value
```

**原因**：配置文件不是有效的JSON格式

**解决**：
1. 检查JSON语法，确保使用双引号
2. 验证JSON在线工具：https://jsonlint.com/
3. 检查文件编码，应为UTF-8

**正确示例**：
```json
{
  "pluginName": "MyPlugin",
  "functions": []
}
```

**错误示例**：
```json
{
  'pluginName': 'MyPlugin',    // 单引号错误
  functions: []                // 缺少引号
}
```

---

### 1.2 输出目录问题

#### 问题：提示"拒绝访问"或"无法创建目录"

**症状**：
```
Error: Access to the path 'C:\Program Files\...' is denied
```

**解决**：
1. 使用管理员权限运行命令行
2. 更换输出目录到用户有权限的位置
   ```bash
   TdxDllGenerator generate -c config.json -o %USERPROFILE%\Documents\MyPlugin
   ```
3. 检查磁盘空间是否充足

---

## 二、编译阶段问题

### 2.1 Visual Studio未安装

#### 问题：提示"找不到cl.exe"或"找不到msbuild"

**解决**：
1. 安装Visual Studio Community（免费）
2. 安装"使用C++的桌面开发"工作负载
3. 或使用Visual Studio Build Tools

**下载地址**：https://visualstudio.microsoft.com/downloads/

---

### 2.2 编译架构错误

#### 问题：编译成功但通达信无法加载

**症状**：DLL在通达信中不显示或提示"不是有效的Win32应用程序"

**原因**：编译成了64位DLL，但通达信是32位程序

**解决**：

**Visual Studio设置**：
1. 项目 → 属性 → 平台 → Win32
2. 配置管理器 → 活动解决方案平台 → Win32

**CMake设置**：
```bash
cmake .. -A Win32    # 必须指定Win32
cmake ..             # 默认可能是x64！
```

**验证架构**：
```bash
dumpbin /headers MyPlugin.dll | findstr machine
# 应显示 14C (x86)
# 如果显示 8664 (x64) 则是错误的
```

---

### 2.3 缺少运行时库

#### 问题：DLL加载时提示"找不到MSVCP140.dll"

**原因**：使用了动态链接的运行时库

**解决**：

**方法一：静态链接（推荐）**
```
项目属性 → C/C++ → 代码生成 → 运行库 → 多线程(/MT)
```

**方法二：安装运行时**
下载安装Visual C++ Redistributable：
https://aka.ms/vs/17/release/vc_redist.x86.exe

---

### 2.4 编译器错误C2664

#### 问题："无法将参数从'const char [*]'转换为'char *'"

**原因**：新编译器对字符串类型更严格

**解决**：
1. 添加编译器选项：/Zc:strictStrings-
2. 或修改代码使用非const字符串

---

## 三、部署阶段问题

### 3.1 找不到DLL目录

#### 问题：不知道通达信的dlls目录在哪里

**查找方法**：

**方法一：通过通达信查找**
1. 打开通达信
2. 菜单 → 系统 → 数据维护工具 → 数据备份
3. 查看显示的目录

**方法二：搜索查找**
```cmd
# 在命令行中搜索
where /r C:\ T0002.dlls
# 或
dir C:\new_tdx* /s /b | findstr dlls
```

**常见路径**：
```
通达信金融终端: C:\new_tdx\T0002\dlls\
通达信64位: C:\new_tdx64\T0002\dlls\
券商定制版: C:\[券商名称]\T0002\dlls\
```

---

### 3.2 DLL复制后消失

#### 问题：复制DLL到目录后，重启通达信文件不见了

**原因**：
1. 被杀毒软件删除
2. 被通达信安全机制移除

**解决**：
1. 添加杀毒软件白名单
2. 检查通达信是否在"安全模式"
3. 尝试重命名DLL为其他名称

---

### 3.3 权限不足

#### 问题：无法复制文件到dlls目录

**解决**：
1. 关闭通达信（占用文件）
2. 以管理员身份运行文件管理器
3. 检查目录权限：
   ```cmd
   icacls "C:\new_tdx64\T0002\dlls"
   ```

---

## 四、导入阶段问题

### 4.1 公式管理器中不显示DLL

#### 问题：绑定DLL列表中没有我的插件

**原因及解决**：

| 原因 | 检查方法 | 解决 |
|------|----------|------|
| 文件名不匹配 | 查看DLL文件名 | 确保与pluginName一致 |
| 架构错误 | dumpbin /headers | 重新编译为Win32 |
| 缺少导出函数 | Dependency Walker | 检查生成代码 |
| 通达信缓存 | - | 重启通达信 |

**详细检查步骤**：

1. 检查导出函数：
   ```cmd
   dumpbin /exports MyPlugin.dll
   ```
   应看到：
   ```
   ordinal hint RVA      name
         1    0 00001000 RegisterTdxFunc
   ```

2. 检查文件位置：
   ```cmd
   dir "C:\new_tdx64\T0002\dlls\MyPlugin.dll"
   ```

---

### 4.2 绑定后提示"DLL调用失败"

#### 问题：绑定成功但使用时报错

**诊断步骤**：

**步骤1：检查依赖**
```cmd
dumpbin /dependents MyPlugin.dll
```
确保所有依赖都存在。

**步骤2：使用Process Monitor**
1. 下载Process Monitor
2. 监控通达信进程的文件访问
3. 查看是否加载DLL失败

**步骤3：事件查看器**
```
事件查看器 → Windows日志 → 应用程序
查找应用程序错误
```

---

### 4.3 函数参数错误

#### 问题：公式中使用DLL函数时参数不匹配

**症状**：公式测试提示"参数个数不匹配"

**解决**：

检查公式调用方式：
```
{ DLL函数格式 }
函数名(数据个数, 输出数组, 输入a, 输入b, 输入c)

{ 通达信公式中 }
MA10: MyMA(CLOSE, 10);  { 正确 }
MA10: MyMA(CLOSE, HIGH, 10);  { 可能错误，取决于定义 }
```

查看生成的函数签名：
```cpp
// PluginTCalcFunc.cpp中
void MyMA(int nCount, float* pOut, float* pIn1, float* pIn2, float* pIn3)
// 参数：nCount=数据个数, pOut=输出, pIn1-pIn3=输入
```

## 五、加密相关问题

### 5.1 时间限制失效

#### 问题：DLL在过期后仍能使用

**原因**：
1. 用户修改了系统时间
2. 检查代码被绕过

**加强方案**：
1. 使用网络时间验证
2. 检查文件创建时间
3. 添加多处隐蔽检查点

---

### 5.2 设备绑定指纹不匹配

#### 问题：同一台机器每次生成的指纹不同

**原因**：使用动态硬件信息（如USB网卡）

**解决**：
1. 使用稳定的硬件标识（主板、CPU）
2. 允许多次尝试匹配
3. 使用模糊匹配算法

---

### 5.3 授权文件损坏

#### 问题：提示"授权文件无效"

**解决**：
1. 检查license.dat是否存在
2. 重新生成授权文件
3. 检查文件编码（应为UTF-8）

---

## 六、性能问题

### 6.1 公式计算缓慢

#### 问题：使用DLL的指标计算很慢

**优化建议**：

1. **减少循环**：
   ```cpp
   // 避免
   for(int i = 0; i < nCount; i++) {
       for(int j = 0; j < nCount; j++) {
           // 双重循环
       }
   }

   // 推荐
   for(int i = 0; i < nCount; i++) {
       // 单层循环
   }
   ```

2. **使用增量计算**：
   ```cpp
   // 均线增量计算
   float ma = prevMA + (newValue - oldValue) / period;
   ```

3. **避免内存分配**：
   ```cpp
   // 避免在循环中分配
   float* buffer = (float*)malloc(size);  // 移到循环外
   ```

---

### 6.2 通达信卡顿

#### 问题：加载DLL后通达信变卡

**原因**：
1. DLL中存在死循环
2. 内存泄漏
3. 异常未捕获

**调试方法**：
1. 使用Visual Studio附加到通达信进程
2. 查看调用堆栈
3. 检查是否有无限循环

---

## 七、调试技巧

### 7.1 添加日志输出

在DLL中添加调试日志：

```cpp
#include <stdio.h>
#include <time.h>

void DebugLog(const char* format, ...) {
    FILE* fp = fopen("C:\\temp\\tdx_debug.log", "a");
    if(fp) {
        // 添加时间戳
        time_t now = time(NULL);
        struct tm* t = localtime(&now);
        fprintf(fp, "[%04d-%02d-%02d %02d:%02d:%02d] ",
            t->tm_year+1900, t->tm_mon+1, t->tm_mday,
            t->tm_hour, t->tm_min, t->tm_sec);

        va_list args;
        va_start(args, format);
        vfprintf(fp, format, args);
        va_end(args);

        fprintf(fp, "\n");
        fclose(fp);
    }
}

// 使用
void MyFunc(int nCount, float* pOut, ...) {
    DebugLog("MyFunc called, nCount=%d", nCount);
    // ...
}
```

### 7.2 使用消息框调试

```cpp
#include <windows.h>

void MsgDebug(const char* msg) {
    MessageBoxA(NULL, msg, "DLL Debug", MB_OK);
}

// 使用
MsgDebug("进入函数");
```

### 7.3 Visual Studio调试

**附加到进程**：
1. 启动通达信
2. 绑定DLL
3. VS → 调试 → 附加到进程 → 选择通达信进程
4. 在代码中设置断点

**注意**：通达信可能有反调试机制

## 八、其他问题

### 8.1 中文显示乱码

**解决**：确保源文件保存为UTF-8 with BOM

### 8.2 浮点数精度问题

**原因**：float精度有限

**解决**：
1. 使用double计算，最后转float
2. 比较时使用epsilon
   ```cpp
   if(fabs(a - b) < 1e-6)  // 相等
   ```

### 8.3 数组越界

**常见错误**：
```cpp
for(int i = 0; i <= nCount; i++)  // 错误：<=
    pOut[i] = ...;

// 正确
for(int i = 0; i < nCount; i++)   // <
    pOut[i] = ...;
```
